# Design Patterns

Design Patterns (ou Padrões de Projeto) são soluções reutilizáveis para problemas comuns de design de software. Eles não são códigos prontos, mas sim estruturas ou templates que podem ser adaptados para resolver situações recorrentes em desenvolvimento de sistemas.

### O que são

- São boas práticas documentadas para organizar o código;
- Ajudam a resolver problemas de forma elegante e padronizada;
- Facilitam a manutenção, legibilidade e escalabilidade de projetos;
- Promovem reuso de soluções e padronização entre equipes.

## Principais categorias

### Creational (Criação)

Focam em formas flexíveis de criar objetos.

- Singleton: Garante uma única instância de uma classe;
- Factory Method: Cria objetos sem expor a lógica de criação;
- Abstract Factory: Cria famílias de objetos relacionados;
- Builder: Constrói objetos complexos passo a passo;
- Prototype: Cria novos objetos a partir de um protótipo.

### Structural (Estruturais)

Tratam da organização de classes e objetos.

- Adapter: Converte uma interface para outra;
- Decorator: Adiciona responsabilidades a um objeto dinamicamente;
- Facade: Fornece uma interface simplificada para subsistemas;
- Composite: Compor objetos em estruturas de árvore;
- Proxy: Representa outro objeto para controlar o acesso.

### Behavioral (Comportamentais)

- Se concentram em comunicação e interação entre objetos.
- Observer: Notifica objetos sobre mudanças de estado;
- Strategy: Permite selecionar algoritmos em tempo de execução;
- Command: Encapsula uma solicitação como um objeto;
- State: Permite que um objeto altere seu comportamento quando seu estado muda;
- Mediator: Centraliza a comunicação entre objetos.

### Exemplos no mundo real

| Design Pattern | Exemplo Real                                             |
| -------------- | -------------------------------------------------------- |
| Singleton      | Gerenciador de conexão com banco de dados                |
| Observer       | Sistema de notificações em redes sociais                 |
| Decorator      | Adicionar funcionalidades extras a uma interface gráfica |
| Strategy       | Seleção de métodos de pagamento em um e-commerce         |

### Por que aprender

- Código mais limpo e legível;
- Facilidade de manutenção e evolução;
- Boa comunicação entre desenvolvedores (fala-se o "mesmo idioma");
- Aplicação de boas práticas de engenharia de software.
